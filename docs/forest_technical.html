Data Forest — Gaze-Controlled 3D Game

A low-poly 3D forest, built in Three.js from the kennye'sMiniforest GLB pack, where the player collects floating data-source orbs using only their gaze. It reuses the Phase 2 gaze engine unchanged and adds a 3D rendering, selection, and game layer on top.

1 Overview

Phase 3 takes the working gaze system from Phase 2 and gives it a 3D world. The player looks around a low-poly forest and collects eight glowing "data-source" orbs — the flood dataset — by resting their gaze on each and holding (dwell). A rigged archer reacts to every pickup; completing the set trains the model and offers a replay, all selected by gaze.

Reuse, not rebuild

The gaze pipeline (webcam → MediaPipe → L2CS gaze model → calibration → 1€ filter → WebSocket) is identical to Phase 2. Calibration is device-and-user specific, not app-specific, so the same calibration_model.pkl drives both the 2D and 3D games. Phase 3 is purely a new front-end that consumes the same ws://localhost:8765 stream.

2 Architecture

  • Maps gaze → a ray into the 3D scene + screen-space aim-assist

Two local processes run together: the gaze server (port 8765) and a static file server (port 8000) that serves the game. The browser loads the game from http://localhost:8000/forest.html and opens a WebSocket to the gaze server.

3 The 3D scene

3.1 · Asset pipeline

  • Three.js is vendored locally (vendor/three/, plus GLTFLoader, OrbitControls, and its BufferGeometryUtils dependency) so the game runs without a CDN. Bare import "three" resolves via an import map in the HTML.
  • The 22 GLB models are copied to models/ with clean names. They reference their texture externally as Textures/colormap.png, so that shared atlas is copied alongside them.
  • A LoadingManager drives the progress bar and reveals the scene when every asset is ready.

3.2 · Composition

A hemisphere + shadow-casting directional "sun" light the scene; sky-blue background with distance fog. A ring of trees, scattered rocks and plants, and a camp (tent, cabin, bridge) form the backdrop. The archer stands centre-stage. All scenery is decorative — only the data orbs are interactive.

4 Gaze in 3D

Turning a 2D gaze point into a 3D selection is the core technique of this phase.

  • Raycast. The gaze (x, y) is converted to normalized device coordinates and a ray is cast from the camera into the scene (THREE.Raycaster). A direct hit on an orb is a precise selection.
  • Screen-space aim-assist. A raw ray against small meshes is unforgiving, so if the ray misses, each orb's world centre is projected to screen pixels and the nearest one within ASSIST_RADIUS (120px) is selected instead. This is the 3D equivalent of the Phase 2 hover-pad, and it is what makes selection feel good.
  • Cursor magnet + stickiness. The on-screen cursor is pulled toward the locked orb, and the current target keeps a distance bonus (hysteresis) so it does not flicker between neighbours.
  • Guided recenter. Pressing c shows a "LOOK HERE" target at screen centre and captures the per-session offset after ~1.3s — removing the guesswork that made a blind recenter unreliable.
Key lesson

3D gaze selection needs aim-assist and fullscreen + recenter for exactly the same reasons the 2D game did. Only orbs are made selectable (not the ~48 scenery props), so the assist has few, well-spaced targets and nothing to confuse.

5 The game layer

  • Data orbs. Eight emissive icosahedra (each a flood data source, e.g. Rainfall Gauge, River Level) float and bob around the archer, each with a screen-projected HTML label and its own point light.
  • Collect. Dwelling on an orb marks it collected: it spins, floats up, and shrinks out; the archer turns to face it and plays its pick-up clip (one of 32 animations, crossfaded back to idle).
  • Win → Train → Replay. Collecting all eight shows a win screen. Its "Train the Model" and "Play Again" buttons are themselves gaze-selectable (2D dwell-to-click), so the loop never needs the mouse. "Train" reports the model accuracy; "Play Again" respawns the orbs.

6 Juice

  • Particles. Each collect spawns a burst of ~18 small emissive shards in the orb's colour, integrated with gravity and faded out over ~0.8s.
  • Sound. All audio is synthesized with the Web Audio API — a pitch-dropping "pop" per collect and an ascending win chime — so there are no audio files to host and nothing is blocked by content security. The audio context is started on the first key-press (browser autoplay rule).

7 Serving

The game uses ES modules (import), which browsers refuse to load over file://. It must therefore be served over HTTP — a one-line static server is enough:

cd "C:\game integration\game\workingGameTemplate"
python -m http.server 8000
# then open http://localhost:8000/forest.html

The gaze server (gaze_server.py) runs alongside it, exactly as in Phase 2.

8 Performance

The asset pack is extraordinarily light, so the scene is trivial for the GPU.
